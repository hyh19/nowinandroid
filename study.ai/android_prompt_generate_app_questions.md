# 生成 Android 应用程序项目的问题列表

## 目的

通过向 AI 大模型提问，系统化、高效地分析和理解 Android 项目代码结构和实现原理，帮助开发者快速掌握陌生项目的核心架构和技术特点，降低学习曲线，提高代码理解和问题诊断效率。

## 任务描述

针对任意 Android 应用程序项目，生成一套结构化、分层次的问题列表，引导开发者通过向 AI 大模型提问的方式，从界面层、业务层、数据层到基础架构层全面了解项目。这些问题将遵循由浅入深、由表及里的认知规律，覆盖从基础概念识别到高级架构设计的多个维度。

## AI 提问最佳实践

当向 AI 大模型提问时，遵循以下指南可以获得更精准的回答：

1. **明确代码位置**：要求 AI 提供：
   - 相对路径（如 `app/src/main/java/com/example/myapp/MainActivity.kt`）
   - 具体的代码行号范围（如第 10-15 行）
   - 关键方法名、类名或变量名的确切位置

2. **提问技巧**：
   - 一次只聚焦一个方面，避免多个问题混合提问
   - 遵循"整体到局部"的分析路径，先了解架构全貌，再深入具体实现
   - 对于复杂功能，先了解关键类的职责定位，再分析它们的协作机制和实现细节

3. **分析路径建议**：
   - 遵循"入口→界面→业务→数据"的分析链路（先分析项目入口 → 界面结构 → 业务逻辑 → 数据处理）
   - 针对特定功能模块，追踪从 UI 层到数据层的完整调用链和数据流
   - 分析典型用例的代码执行路径，识别项目中应用的设计模式和架构思想

4. **绘图需求说明**：
   - 所有需要图表可视化的需求，统一使用 Mermaid 语法实现
   - 根据图表内容选择最合适的图表类型（流程图、序列图、类图、状态图等）
   - 设计图表时，确保节点命名和关系描述清晰准确，易于理解

## 问题分类框架

1. **按难度划分**
   - 1.1 **初级问题**：聚焦基础概念识别和结构定位
     - 例：项目使用了哪些网络请求库？
     - 例：应用的主要界面组成有哪些？
     - 特点：答案直观明确，通常通过简单的文件查找或代码扫描即可获得

   - 1.2 **中级问题**：聚焦实现原理和交互机制
     - 例：界面状态如何在不同组件间传递和同步？
     - 例：不同屏幕尺寸的布局适配是如何实现的？
     - 特点：需要理解代码逻辑和流程，通常需要分析多个相关类的协作关系

   - 1.3 **高级问题**：聚焦架构设计和优化策略
     - 例：项目的模块化架构是如何设计的？各模块间如何通信？
     - 例：应用的性能瓶颈如何识别和优化？
     - 特点：需要综合分析系统设计意图和技术取舍，通常涉及到跨模块的宏观视角

2. **按层级划分**
   - 2.1 **界面层**：UI 组件、布局系统、动画效果、用户交互
   - 2.2 **业务层**：状态管理、导航机制、权限控制、业务逻辑
   - 2.3 **数据层**：网络请求、本地存储、数据同步、缓存策略
   - 2.4 **基础架构层**：依赖注入、线程管理、日志系统、错误处理
   - 2.5 **工程化与构建**：编译配置、多环境支持、自动化流程、性能监控

3. **按认知深度划分**
   - 3.1 **是什么(What)**：聚焦组件识别和功能定位
     - 例：项目中使用了哪些自定义 UI 组件？
     - 特点：回答"存在什么"的问题，识别项目中的关键元素和组件

   - 3.2 **如何做(How)**：聚焦实现机制和处理流程
     - 例：深层链接(Deep Link)是如何被处理和路由的？
     - 特点：回答"怎么实现"的问题，解析具体的技术实现方案

   - 3.3 **为什么(Why)**：聚焦设计理念和决策依据
     - 例：为什么选择这种特定的架构模式而非其他方案？
     - 特点：回答"为何如此"的问题，探讨技术选型和架构决策的背后原因
